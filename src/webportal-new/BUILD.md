# Build Instructions for webportal-new

## Building with Docker

### Option 1: Using pai-build (Recommended for LTP Platform)

The pai-build system will automatically run `build-pre.sh` before building the Docker image.

```bash
# From the ltp-platform root directory
python pai-build \
  --service webportal-new \
  --image-tag your-tag
```

### Option 2: Manual Docker Build

If building manually, you need to prepare the build environment first:

```bash
cd /home/ruigao/ltp-platform/src/webportal-new

# Step 1: Run build-pre.sh to prepare dependencies
./build/build-pre.sh

# Step 2: Build the Docker image
docker build \
  -f build/webportal-new.common.dockerfile \
  -t webportal-new:latest \
  .
```

## What build-pre.sh Does

The `build-pre.sh` script prepares the following files needed for the Docker build:

1. **dependency/** directory
   - Copies `docs/` from the root directory
   - Copies `examples/` from the root directory

2. **openpai-js-sdk/** directory
   - Copies the local `openpai-js-sdk` from `src/openpai-js-sdk/`
   - This is needed because the SDK is referenced as `"file:../openpai-js-sdk"` in package.json
   - The Docker build context is `src/webportal-new/`, so the SDK must be copied into this directory

3. **version/** directory
   - Copies version files from the root `version/` directory
   - PAI.VERSION: Platform version (e.g., v1.8.1)
   - COMMIT.VERSION: Git commit ID (first 6 characters)
   - K8S.VERSION: Kubernetes version

These files are used during the Docker build to:
- Set the correct version in package.json
- Include documentation and examples in the image
- Track the build version and commit
- Build the local openpai-js-sdk dependency

## Building Locally (Development)

For local development without Docker:

```bash
cd /home/ruigao/ltp-platform/src/webportal-new

# Install dependencies
npm install
# or
yarn install

# Create .env file
cp .env.example .env
# Edit .env with your configuration

# Development mode
npm run dev

# Production build
npm run build
npm start
```

## Troubleshooting

### Error: "dependency/": not found

This means `build-pre.sh` was not run before the Docker build. Run it manually:

```bash
cd /home/ruigao/ltp-platform/src/webportal-new
./build/build-pre.sh
```

### Error: version/PAI.VERSION not found

Make sure you're running the build from the correct directory and that the root `version/` directory exists. The `build-pre.sh` script will create a default version if the root version directory is not found.

## Files Generated by build-pre.sh

After running build-pre.sh, you should see:

```
webportal-new/
├── dependency/
│   ├── docs/
│   └── examples/
├── openpai-js-sdk/
│   ├── package.json
│   ├── src/
│   └── ... (complete SDK source)
└── version/
    ├── PAI.VERSION
    ├── COMMIT.VERSION
    └── K8S.VERSION
```

These directories are listed in `.gitignore` and should not be committed to the repository.

## Clean Up

To clean up generated files:

```bash
cd /home/ruigao/ltp-platform/src/webportal-new
rm -rf dependency/ version/ openpai-js-sdk/
```

The pai-build system will regenerate these files automatically on the next build.
